# REO — RE-Environment Ontology (v1.1.0) and EC-RE reference checker

Replication package for *Environment Engineering for Requirements Engineering: The REO Ontology
and an Executable Derivation Contract* (IEEE Access, revised version).

REO models the socio-technical environment of a system as seven typed views
(actors, goals, domain, constraints, contexts, uncertainties, interactions). The derivation
contract decides, for a candidate requirement and its explicit mapping to environment elements,
one of six states (accepted, accepted with reservations, conditional, pending review, rejected,
not derived) and records the identifiers it consulted (the trace). Decision records are
serialised with PROV-O.

## Layout

| Path | Content |
|---|---|
| `ontology/reo-core.ttl` | Seven views, auxiliary classes, restrictions, disjointness, validator binding, identity migration |
| `ontology/reo-derivation.ttl` | Requirements, decision states, PROV-O-aligned decision records |
| `ontology/reo-shapes.ttl`, `ontology/reo-derivation-shapes.ttl` | SHACL obligations |
| `examples/medical-emergency/` | Emergency-prescription environment, extension, ten requirements |
| `test-cases/` | Three SHACL regression fixtures |
| `reo_checker.py` | Reference implementation of the contract, change impact, identity migration, PROV-O records |
| `prototype.py` | 18 regression scenarios, 4 impact queries, 20 targeted regressions (RDF mutations + SHACL) |
| `scripts/sparql_oracle.py` | Independent SPARQL encoding of the contract (differential testing) |
| `scripts/run_evaluation.py` | Schema-derived mutation corpus, baselines, impact and trace precision/recall |
| `scripts/` (other) | Reasoner, SHACL, competency questions, pitfall scan, migration, metrics, figure, paper macros |
| `evaluation/` | Competency questions, view-derivation coding, v1.0.0 baseline copy, study kits |
| `evaluation/llm-evaluation/` | Blinded evaluation by language models (E1 test authoring, E2 hand application, E3 view recoding): packs, prompts, frozen outputs, audit, scoring |
| `results/` | Recorded outputs used in the paper |
| `generated/` | LaTeX macros/tables generated from `results/`; vocabulary inventory |

## Reproduce

```bash
python -m pip install -r requirements.txt   # Python 3.13; Java 21 for HermiT; Graphviz for the figure
python scripts/run_all.py                   # ~15 min on two cores (mutation corpus included)
python scripts/run_all.py --skip-corpus     # ~1 min, reuses results/evaluation_summary.json
```

Single steps: `python prototype.py`, `python scripts/run_competency_questions.py`,
`python scripts/reasoner_check.py`, `python scripts/run_shacl.py`, `python scripts/run_evaluation.py`.

Standalone SHACL check of the example:

```bash
python -m pyshacl -s ontology/reo-shapes.ttl -e ontology/reo-core.ttl -i rdfs --allow-warnings \
  -f human examples/medical-emergency/hospital.ttl
```

## Scope

Implemented and evaluated: the ontology modules, SHACL shapes, the decision contract over manually
annotated requirements, read-set traces, PROV-O records, direct/transitive re-evaluation, identity
migration with `reo:supersededBy`. Not implemented: natural-language proposition extraction,
multi-source fusion and entity resolution, runtime synchronisation, LLM-based generation.
Analyst effort has not been measured; `evaluation/human-study/` contains a prospective pilot protocol
and `evaluation/independent-evaluation/` an authoring/freezing protocol for external evaluators.
That protocol was executed with language-model agents instead of people
(`evaluation/llm-evaluation/`, paper Section VIII-E); it is a proxy, not a human study.

The medical example is a synthetic fixture. Identifiers such as `C001_HIPAA` and `C002_FDA` are
illustrative labels, not interpretations of the regulations.

## Note on `results/evaluation_summary_run1.json`

This file records the *first* differential-testing run (766 mutants, before the conflicting-value
operator was added), which exposed 19 disagreements caused by three defects later fixed in
`reo_checker.py` and `scripts/sparql_oracle.py`. It is kept as a historical record and is not
regenerated by `run_all.py`; the paper reports it in Section VIII-C.
